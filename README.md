**EtherSync** 是一套面向 Paper / Bukkit 的跨服互通插件。多台服务器共用同一份 MySQL 后，玩家可在大厅查看对端是否在线，并通过市场、运输箱、红石与聊天彼此往来。游戏内指令为 `/link`，别名 `/eslink`、`/互通`。版本号以 [`src/main/resources/plugin.yml`](src/main/resources/plugin.yml) 与 [GitHub Releases](https://github.com/EVGA2048/EtherSync-Link/releases) 为准；新版本可能增补配置键，但不会改写您已经填写的值。

## 介绍

EtherSync 最初为两台模组构成接近的生存服务器而写：玩家往返两地时，箱子与生产线无法随人过去。其中一台即 EtherStories（以太物语）。项目因此做成「大厅 + 节点」：在本服打开 `/link`，即可看到对端状态，并办理市场、运输、红石与聊天。游戏内插件名为 ESLink，发行文件亦使用这一名称，以便既有软依赖（例如 ES2UniPlugin）按插件名识别。

请先明确它**不会**做的事情，以免按实时管道或跨服银行来理解：

- **运输箱不是实时管道。** 默认大约每 2 秒扫描一轮，每轮只发送有限组数；路上队列满了会暂停，而不会把物品刷丢。
- **货款只在买家所在服务器的 Vault 账户上结算。** 卖家收到的是该服务器上的余额，不会自动打入对端服务器的账户。
- **独立市场服务只保管货单，不记账、不扣款。** 购买时它删除对应货单；扣款与发放物品均在买家那一台 Minecraft 服务器上完成。
- **聊天与箱子始终走插件所连的 MySQL**，与是否启用市场服务无关。

## 功能一览

- **大厅**：顶部一排显示各服在线状态（默认约 5 秒心跳，约 20 秒无心跳视为离线）。
- **跨服市场**：上架、浏览、购买、下架、改价；同一账号可在外服取回自己的货（另收取得回费）。
- **运输箱**：发送箱（TX）、接收箱（RX）与回退箱配对，供生产线周期性送货。
- **红石**：对准红石灯建立节点；电平变化才写入数据库，接收端按时间戳回放 0–15。
- **聊天选台**：发言可限本服或发往全部互通服；接收可关闭、全收或按服勾选。
- **互通钱包**：按各服汇率，把本服货币存为互通余额，再到另一台服务器取出。
- **取件码**：离线认证环境下防止冒名下架；亦可发给他人代领。

## 数据如何存放

| 组件 | 存放位置 | 用途 |
|---|---|---|
| 插件连接的 **MySQL** | 各服必须使用**同一套**数据库 | 心跳、聊天、运输箱、红石、上架通知；未登记独立市场时，货单也在此库 |
| **市场服务**（可选） | 独立的 Python 进程，自带 SQLite | 货单的上架、列表、下架与买走 |

货单有两种去向，请按您的部署选择其一，不要混用后指望自动搬家：

- 配置中 `markets.list` 为空时，货单继续写入上方 MySQL，与早期版本相同。
- **一旦登记了任一市场，新上架将改走 HTTP。** 库中既有货单不会自动迁移。您需要重新上架，或暂时不要登记市场、继续使用旧库。

其他服务器若只需加入你们的市场、而不自建数据库，可只连接市场服务；聊天、箱子与红石仍要求各服都能访问那份 MySQL。

## 运行环境

每一台加入互通的服务器均需要：

- **Java 21**
- **Paper 1.21+**。Youer、Arclight 亦曾验证可用。聊天与签名数据包相关，更换核心后请先执行 `/link chat` 确认本服发言与外服接收均正常。
- 各服均能访问的 **MySQL**

可选组件：

- **Vault** 与经济插件。未安装时，标价为 0 的物品仍可上架；标了价格则无法完成购买。
- **ES2UniPlugin**：当 `trade.sink-account` 留空时，插件会尝试读取其 `tax.sink-account` 作为税账户。
- **Python 3.10+**：仅在启用独立市场服务时需要，使用标准库即可，无需安装 pip 依赖。

## 安装

1. 将当前发行版的 `ESLink-<版本>.jar` 放入各服的 `plugins/` 目录，启动一次服务器。插件将生成 `plugins/ESLink/config.yml`。
2. 将各服的 MySQL 填写为**同一套**主机、端口、库名、用户与密码。
3. 为每一台服务器单独修改 `server` 段：
   - `code`：内部代号，仅限字母与数字，**全网不可重复**。牌子配对使用此字段。
   - `short`：聊天前缀短标签，例如 `ES2`、`SNC`。留空则使用 `code`。
   - `name` / `blurb`：大厅中显示的名称与一句简介。
   - `icon`：`TERRACOTTA`（陶瓦）或 `CONCRETE`（混凝土）。
   - `color`：大厅标识颜色，外服聊天前缀亦使用此色。可选值包括 `WHITE`、`LIGHT_GRAY`、`GRAY`、`BLACK`、`BROWN`、`RED`、`ORANGE`、`YELLOW`、`LIME`、`GREEN`、`CYAN`、`LIGHT_BLUE`、`BLUE`、`PURPLE`、`MAGENTA`、`PINK`。
4. 在游戏内执行 `/link reload`（需要 `eslink.admin`）。

新版本启动时会自动补全缺失的配置键，不会覆盖您已经填写的值。大厅顶部一排即为各服在线状态。

## 使用方法

平时打开 `/link` 即可进入大厅。准星对准箱子或红石灯再执行 `/link`，将进入该节点的菜单。完整说明书亦在大厅最下方，或执行 `/link help`。

### 市场

在大厅中选择「跨服市场」。若管理登记了多个市场，可在顶栏点按名称切换。**切换市场即切换一份货单**，不同市场中的货物不会混在一起。

上架：主手持有物品，点按上架，关闭界面后在聊天栏输入**单价**。输入 `cancel` 可取消。浏览时，左键购买，右键查看卖家。「我的上架」中，左键下架（物品返回背包），右键改价。

请注意：

- 本服由您自己上架的货物不能购买，请使用下架。
- 同一账号在**另一台服务器**上的货物可以取回：物品回到当前服务器，货款不会打给您自己，仅收取一笔取回费（可关闭；含保底、冷却与每日次数，详见[经济与钱包](#经济与钱包)）。
- 本服未安装的模组物品无法购买。对端缺失的附魔默认仍会送达，并在物品上标注；将物品带回原服后，附魔一般可以恢复。
- 上架通知默认关闭，玩家可在大厅中自行开启；管理端另有总开关。

### 聊天

在大厅中打开聊天页：

- **发言**：仅本服，或发往聊天网上的全部服务器。
- **接收**：不接收外服（默认）、全部接收，或按服务器勾选。陶瓦颜色即该服的主题色。

外服消息形如 `[ES2] 玩家: 内容`。短标签取自各服的 `server.short`，颜色与大厅标识一致。发言过快时，该条不会传到其他服务器，本服仍可看见。

- `/link msg <玩家> <内容>`：跨服私聊。
- 聊天中输入 `[i]`：附带主手物品（需 `chat.item` 为开启）。
- `/link ignore player <名称>`、`/link ignore server <服名>`：屏蔽。勾选是「希望听见谁」，屏蔽是另一套规则，两者同时生效。

若本服同时安装了 ES2UniPlugin，网页终端可将发言写入互通库。网页上「发往全部服」的偏好目前保存在内存中：插件重载或重启后，若玩家不在线，将回到 `chat.default`（默认 `local`）。

### 运输箱

准星对准箱子（建议距离约 5 格），执行 `/link chest`，或从大厅进入。亦可使用 `/link stick` 取得调试棒，点按箱子即可，无需潜行。

请先将箱子设为 **TX（发送）** 或 **RX（接收）**，再与对端配对。发送箱必须另外绑定一口**回退箱**：对端没有的物品、未能发出的物品，将回到回退箱。回退箱已满时，发送会暂停，物品不会丢失。

运输面向生产线：大约每 2 秒一轮，每轮发送 `chest.stacks-per-scan` 组；路上积压达到 `chest.queue-limit` 时 TX 暂停。请勿用漏斗将 TX 与 RX 对向灌注。

纸箱、潜影盒会连同内容一并传输，并在基础倒计时上再叠加等待。TX 可按物品或模组名过滤；空手点按过滤即可清除。

潜行点按牌子打开菜单。拆除需要确认两次。仅主人与管理可修改或拆除。大厅中的「我的节点」可指向本服坐标。

### 红石

请将准星对准**灯本身**，而不是旁边的方块，然后执行 `/link io`。灯亮表示对端在线，离线变为灰色，异常变为红色。接收灯输出强度为 0–15；对端掉线、心跳超时或区块未加载时，输出固定为 0。

仅在电平发生变化时写入 MySQL，接收端按时间戳回放，而不是每个游戏刻写一次。接收端可切换为正常、反向或满信号。

## 独立市场服务

[`market-server/`](market-server/) 提供一个自带 SQLite 的 Python 进程，用于单独存放货单，无需再为货单搭建数据库。聊天、箱子与红石不会进入该进程。

```bash
cd market-server
python3 etherlink_market.py --name 以太货栈 --port 8765
```

首次启动将在 `data/market.json` 写入令牌，并在终端打印。货单位于 `data/market.sqlite`。使用 `--data` 更换目录即得到另一份市场。命令行参数与管理页说明见 [market-server/README.md](market-server/README.md)。

在游戏内（需要 `eslink.admin`）：

```
/link market add ether http://127.0.0.1:8765 令牌 以太货栈
/link market default ether
/link market
```

上述命令会写入 `config.yml`，重启后仍然有效。玩家只能在界面中切换市场名称，看不到地址与令牌。您也可以直接编辑配置：

```yaml
markets:
  default: ether
  list:
    ether:
      name: 以太货栈
      url: http://127.0.0.1:8765
      token: "与市场服务相同的令牌"
```

多台服务器连接同一市场时，请将 `url` 写成**那一台服务器能够访问到的地址**。若市场进程不在本机，请勿填写 `127.0.0.1`。放行端口即可；请勿将令牌提交到版本库。

## 经济与钱包

跨服买卖需要 Vault。货单以**互通货币**记账。`trade.link-rate` 表示：1 单位本服货币 = 该数值的互通货币。玩家上架时输入的是本服价格，插件乘以汇率后写入货单；买家界面再换算回本服货币。

若已连接独立货栈，各服汇率默认由货栈根据近窗**跨服成交**自动调整：外服买走本服货物较多时，卖方汇率升高（本币更贵）；本服买外服货物较多时回落。公式可在货栈网页或命令行中修改。游戏内点按汇率的加减，会将该服钉为手动；再点按向日葵可切回自动。未连接货栈时，仅读取本服配置。默认值为 `1.0`。管理可在 `/link settings` 中调节（单击 ±0.1，潜行 ±0.01）。

`trade.tax-rate` 在**买家所在服务器**收取，卖家仍获得换算后的标价（不含税）。税款进入 `trade.sink-account`；若留空，则尝试 ES2UniPlugin 的 `tax.sink-account`；两者皆空则税款不入账。

**互通钱包**（大厅中的金锭，或 `/link wallet`）用于同一 UUID 在各服之间转账：本服存入时乘以本服汇率，记入共享 MySQL 中的互通余额；到另一台服务器取出时，再除以当地汇率，兑成当地货币。此流程不经过市场服务。`trade.wallet: false` 可关闭。

首次存入将获得 6 位钱包码，取出时必须输入。钱包页可随时再次查看，亦可改为更好记忆的 6 位数字（需先核对当前码）。较早版本仅显示一次、且库中没有明文的码无法再取出；若您仍记得旧码，可据此改掉，或请管理执行 `/link pinreset`。

离线服务器（未开启正版验证）上，UUID 往往等于玩家名，他人可能冒名操作。因此默认 `trade.claim-code: true`：只能在上架那一台服务器下架或改价。取件码在全网唯一，上架服的「我的上架」可随时再看，也可发给他人代领。领取时输入码后，需点出货主头像（五个本服见过的头像）。连续输入不存在的码达到上限，或点错头像，将暂停取件并通知管理。没有取件码的旧货，只能回到上架服下架。管理可使用 `/link pinreset <玩家>` 清除钱包码。

同一 UUID、货物位于外服时，称为**取回**：

- 费用为 `max(保底, 税 + 标价抽成)`，保底默认 64。
- 默认冷却 20 秒，每日 12 次（按 UTC 日切换，与部分服务器的本地签到日界不必相同）。
- `trade.self-buy: false` 将关闭整段取回，只能前往上架所在服务器下架。

当税率为 0 时，若仍把货款打回自己，便等于免费将物品从 A 服搬到 B 服。因此取回时货款故意不入账，只收取回费。

## 物品如何跨服

原版物品按 Bukkit / Paper 数据传输。模组物品依据 namespaced key，**两端都必须安装该模组**。非原版物品尽量走 NBT，以免数字 ID 对不上。

纸箱、潜影盒按内部物品拆开传输：缺失的若干件退回，其余照常到达。每一批都会校验，失败则整批扣下，不会把损坏数据交给玩家。

对端缺少的附魔或属性，默认仍送达（`chest.unknown-extra: deliver`），并在物品上留下说明；改成 `refuse` 则整件退回。带回原服后，这些标记一般可以恢复。旧版残留标记可用 `/link cleanitem` 清除。

`whitelist` 为空表示不限制。正式服务器请写成 `minecraft:iron_ingot` 这样的 namespaced key。某个数据组件引发问题时，可先用 `/link component block <id>` 拦截。

潜影盒、包裹等带内容的容器，默认 `chest.containers: auto`：启动自检通过后才收发。请查看 `/link diag`；若失败，可执行 `/link diag retry`。

## 常见误解与配置注意

以下各项请在上线前逐条核对。每一条先给出正确做法，再说明若未遵守会发生什么。

1. **`server.code` 必须在全网唯一。** 请使用互不相同的字母数字代号。重复时，牌子配对、大厅在线状态与运输目标都会指向错误的一端。
2. **各服必须连接同一套 MySQL。** 库不同则看不到对端心跳，聊天、箱子与红石均无法互通。仅启动插件、未填写数据库时，大厅可以使用，但跨服功能不会工作。
3. **未登记市场时，货单仍在 MySQL；登记之后，新上架改走 HTTP。** 旧货不会自动搬进市场服务。若您仍有未售出的旧货，请先下架重上，或暂时不要执行 `/link market add`。
4. **外服填写的市场 `url` 必须是该服能够访问的地址。** 市场进程若在另一台机器上，请勿写 `127.0.0.1`。写错后大厅可能显示市场离线，上架与购买会失败。
5. **离线认证请保持 `trade.claim-code: true`。** 关闭后，知道玩家名的人即可在其他服务器冒名下架或改价。
6. **请勿将 0.2.4 及更早的版本与 0.2.5+ 混跑后再启用动态汇率。** 聊天、箱子、红石与心跳可以共存；多出的字段会被旧版本忽略。但旧版本心跳不写入 `link_rate`，市场价会按 1:1 理解，两边价格会对不齐。在对方升级之前，请将新服汇率钉为 **1:1**，或等待双方均升至 0.2.5 及以上。
7. **`whitelist` 为空表示允许任意物品。** 正式服请列出允许的 namespaced key。刷怪笼、创造物品以及本服没有的模组物品，都可能被运走或上架。紧急时可执行 `/link transport off`。
8. **请勿将红石改为每个游戏刻写入 MySQL。** 两端 TPS 不一致时，数据库会被迅速写满，且电平无法对齐。请保持「电平变化才写入」。
9. **请勿用漏斗将 TX 与 RX 对向灌注。** 物品会在两端之间来回排队，看起来像丢失或刷物。生产线应单向：产出 → TX，对端 RX → 消耗。
10. **回退箱已满时，发送会暂停，物品留在发送箱中。** 这是保护，不是故障。请清理回退箱后再等待下一轮扫描。
11. **本服没有的模组物品既买不到，也运不过来。** 缺失的附魔默认仍会送达并带说明；若希望整件退回，请将 `chest.unknown-extra` 设为 `refuse`。
12. **网页终端「发往全部服」目前只记在内存中。** 插件重载或重启后，若玩家不在线，将回到 `chat.default`。进服后以玩家数据为准。
13. **上传到服务器时，请只使用当前发行版对应的 jar**（例如 `ESLink-0.2.9.jar`）。`dist/` 目录中可能留有历史构建，请勿一并复制。
14. **令牌、数据库密码与市场地址不要写入公开仓库。** `market-server/data/` 已列入 `.gitignore`。

## 配置键

`config.yml` 各段均有中文注释。下列键较容易设错：

| 键 | 含义 |
|---|---|
| `server.code` | 本服内部代号，全网不可重复 |
| `server.short` | 聊天前缀；留空则使用 `code` |
| `heartbeat-seconds` / `offline-after-seconds` | 心跳间隔，以及多久无心跳视为离线 |
| `chest.stacks-per-scan` | 每一轮最多发送的组数 |
| `chest.queue-limit` | 路上允许积压的数量，满则 TX 暂停 |
| `chest.batch-delay-seconds` | 发货前等待的秒数；`0` 表示立即发送 |
| `chest.heavy-delay-seconds` / `heavy-max-seconds` | 纸箱、潜影盒在基础等待之上再叠加的时间 |
| `transport.enabled` | 运输总开关；游戏内 `/link transport off` 亦可立即停止 |
| `io.enabled` / `io.stale-ms` | 红石总开关，以及对端多久未更新视为过期 |
| `trade.*` | 买卖、税率、钱包、取回与取件码 |
| `markets.*` | 独立市场列表，可以全部留空 |
| `chat.default` | 新玩家默认 `local`：不向外发言，也不接收外服 |
| `chat.fast-window-seconds` / `fast-count` | 发言过快时拦截发往外服的窗口与次数 |
| `super-admins` | 可删除大厅中残留的错误服务器记录；持有权限 `eslink.super` 亦可 |

## 指令与权限

| 指令 | 作用 |
|---|---|
| `/link` | 打开大厅；准星对准箱子或灯时进入该节点 |
| `/link chest` | 运输箱 |
| `/link io` | 红石 |
| `/link tx` / `/link rx` | 将眼前的箱子设为发送 / 接收 |
| `/link stick` | 取得调试棒 |
| `/link chat` | 聊天选台 |
| `/link chat local` / `all` | 发言范围 |
| `/link msg <玩家> <内容>` | 私聊 |
| `/link ignore` / `unignore` | 屏蔽与取消屏蔽 |
| `/link help` | 说明书 |
| `/link settings` | 管理设置 |
| `/link wallet` | 互通余额（同一账号跨服转账） |
| `/link claim` | 输入取件码领取（可代领） |
| `/link pinreset <玩家>` | 清除钱包码（管理） |
| `/link cleanitem` | 清除占位标记 |
| `/link reload` | 重载配置（管理） |
| `/link market …` | 登记或查看市场（管理） |
| `/link transport on` / `off` | 运输急停 |
| `/link diag` / `retry` / `io` | 诊断 |
| `/link component …` | 禁用某个数据组件 |
| `/link log` | 日志 |
| `/link version` | 版本 |

`eslink.use`、`eslink.chest` 默认授予所有人。`eslink.admin`、`eslink.super` 默认授予管理员（OP）。`/link market add <代号> <地址> <令牌> [名称]` 会写入配置并在重启后保留。

## 构建

```bash
mvn -q package
```

产物位于 `target/ESLink-<version>.jar`，并会再复制一份到 `dist/`。请将当前版本的这一份用于部署，而不要混用目录中的旧文件。

## 适用范围与参与

本插件建议用于公益服务器之间的互通，不建议与以营利为目的的商业服务器相互连接。即便同为公益服，也请仅接入您充分信任、能够共同维护安全的服务器。互通一旦建立，物品、聊天与部分经济数据便会在两端之间流动；接入不可信的节点，可能带来安全风险。

本插件目前仍处于测试阶段，功能与配置仍可能调整。欢迎您加入开发与讨论；若发现缺陷，请通过 [Issue](https://github.com/EVGA2048/EtherSync-Link/issues) 反馈。改进亦欢迎以 [Pull Request](https://github.com/EVGA2048/EtherSync-Link/pulls) 的形式提交。
